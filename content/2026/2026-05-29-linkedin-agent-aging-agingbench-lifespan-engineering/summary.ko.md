# 요약 - 에이전트도 늙습니다: AgingBench와 에이전트 노화

## 한 줄 요약
염기웅의 LinkedIn 글은 UT Austin의 AgingBench 논문을 바탕으로, 장기 운영되는 AI 에이전트가 모델 가중치가 고정되어 있어도 메모리 압축, 간섭, 수정, 유지보수 과정에서 성능이 조용히 무너질 수 있다고 설명한다.

## 핵심 내용
- **문제 제기:** day-one 벤치마크가 높은 모델이라도, 실제 배포 후 여러 세션을 지나며 에이전트의 작업 상태와 메모리 사용 방식이 변하기 때문에 신뢰성이 감소할 수 있다.
- **압축 노화:** 대화/작업 이력을 요약하거나 압축하는 과정에서 나중에 필요한 수치, 제약, 설계 결정이 빠져 성능 반감기가 짧아질 수 있다.
- **조용한 정밀도 붕괴:** 행동 규칙이나 말투는 정상으로 보이지만, 예산/일정/상태 같은 정밀한 값만 틀리는 실패가 발생한다. 겉보기 compliance 지표만으로는 탐지하기 어렵다.
- **기록-검색 격차:** 에이전트가 파일이나 메모를 비교적 잘 남겨도, 최종 문제 풀이 시 필요한 기록을 충분히 다시 읽고 활용하지 않으면 결과가 무너진다.
- **모델 크기만으로 해결되지 않음:** 논문은 여러 모델과 메모리 정책을 비교하며, 어떤 모델이 모든 aging mechanism에서 일관되게 우월하지 않다고 주장한다.
- **운영적 함의:** 장기 에이전트 운영에는 단발성 성능 평가보다 lifespan engineering, 메모리 정책, 강제 재읽기, 상태 재계산, 유지보수 이벤트 후 회귀 테스트가 필요하다.

## 재사용 시 주의
- LinkedIn 글은 논문 수치를 강한 비유와 해석으로 풀어쓴 2차 해설이다. “치매”, “반치매”, “최고 존엄” 같은 표현은 작성자의 설명 방식이지 논문의 공식 용어가 아니다.
- GPT-5-mini, Claude Haiku/Opus 4.x 등 구체 모델 수치는 논문 Table 3 / Figure 7의 특정 실험 조건에서 나온 값이다. 제품 전체 성능이나 모든 장기 에이전트 환경으로 일반화하면 안 된다.
- 핵심 실무 메시지는 “장기 에이전트는 모델만 평가하지 말고 메모리 파이프라인과 운영 수명 전체를 평가해야 한다”이다.

## 짧게 공유할 때

Ouroboros는 AI 코딩을 “프롬프트” 중심이 아니라 “명세” 중심으로 바꾸려는 도구입니다. 사용자가 막연하게 “이런 걸 만들고 싶다”고 말하면, 바로 코드를 만들기보다 먼저 질문을 통해 숨은 가정과 빠진 조건을 드러냅니다. 그다음 명세를 만들고, 그 명세를 기준으로 실행과 평가를 반복합니다.

핵심 메시지는 간단합니다. AI가 코드를 못 짜서 실패하는 경우보다, 사람이 무엇을 만들지 충분히 정하지 않은 채 시작해서 실패하는 경우가 많다는 것입니다.

## 조금 길게 설명할 때

Ouroboros는 “Stop prompting. Start specifying.”라는 문구를 내세우는 오픈소스 프로젝트입니다. 말 그대로 AI에게 그때그때 프롬프트를 던지는 방식에서 벗어나, 먼저 요구사항과 성공 기준을 명세로 확정한 뒤 작업을 진행하자는 접근입니다.

흐름은 대략 다음과 같습니다.

1. Interview: 사용자의 아이디어를 질문으로 파고들어 모호한 부분을 찾습니다.
2. Seed: 답변을 바탕으로 실행 가능한 명세를 만듭니다.
3. Execute: 명세에 맞춰 실제 구현을 진행합니다.
4. Evaluate: 결과가 명세와 맞는지 기계적 검사, 의미 평가, 여러 모델의 합의 방식으로 검증합니다.
5. Evolve: 평가 결과를 다시 다음 명세에 반영합니다.

이 프로젝트가 흥미로운 이유는 AI 코딩의 문제를 단순히 “더 좋은 모델을 쓰면 된다”로 보지 않는다는 점입니다. 오히려 입력의 품질, 즉 사람이 문제를 얼마나 잘 정의했는지가 더 중요하다고 봅니다. 그래서 코드 작성 이전의 질문, 명세화, 평가 루프를 하나의 운영체제처럼 묶으려 합니다.

## 무엇을 해결하려는가

- 막연한 요구사항으로 AI가 추측해서 코딩하는 문제
- 중간에 목표와 구조가 흔들리는 문제
- “그럴듯해 보이는 결과물”을 실제 검증 없이 통과시키는 문제
- 개발이 끝난 뒤에야 숨은 가정이 드러나 재작업이 커지는 문제

## 주요 기능

- `ooo interview`: 아이디어를 질문으로 구체화
- `ooo seed`: 인터뷰 결과를 명세로 정리
- `ooo run`: 명세 기반 실행
- `ooo evaluate`: 결과 검증
- `ooo evolve`: 평가 결과를 다음 세대 명세에 반영
- `ooo ralph`: 수렴할 때까지 반복 실행하는 지속 루프

## 지원하는 실행 환경

README 기준으로 Claude Code, Codex CLI, OpenCode, Hermes를 지원합니다. Hermes용 가이드도 별도로 들어 있으며, `ouroboros setup --runtime hermes` 명령으로 Hermes 스킬 설치와 MCP 서버 등록을 하도록 설계되어 있습니다.

## 현재 상태 메모

2026-05-05 확인 기준으로 GitHub 저장소는 약 3.3천 개의 star, 300개 이상의 fork를 가지고 있습니다. PyPI에는 `ouroboros-ai` 패키지로 배포되어 있고, 확인 시점의 최신 버전은 0.33.0입니다. Python 3.12 이상이 필요하며, 라이선스는 MIT입니다.

로컬에서 저장소를 얕게 클론해 확인했을 때 대략 791개 파일, 18MB 정도의 규모였습니다. Python 파일과 테스트가 많고, 문서와 런타임 가이드도 비교적 잘 갖춰져 있습니다. 단순한 아이디어 README만 있는 프로젝트라기보다는 실제 패키지와 테스트, CLI, MCP 연동, 런타임 어댑터를 갖춘 프로젝트로 보입니다.

## 좋게 보이는 점

- AI 코딩 실패의 원인을 “출력 품질”보다 “입력의 불명확함”에서 찾는 관점이 좋습니다.
- 질문, 명세, 실행, 평가, 재시도 루프가 명확합니다.
- Claude Code, Codex CLI, Hermes 같은 여러 런타임을 염두에 둔 구조입니다.
- 명세와 평가를 중심에 두기 때문에 팀 작업이나 외부 공유용 개발 프로세스에 응용하기 좋습니다.

## 조심해서 볼 점

- 설치 스크립트가 로컬 환경을 감지해 여러 설정을 자동으로 만집니다. 바로 `curl | bash`로 설치하기보다는 격리 환경에서 먼저 테스트하는 편이 안전합니다.
- 현재 Hermes, Claude, Codex가 모두 설치된 환경에서는 어떤 런타임으로 설정될지 주의해서 봐야 합니다.
- 프로젝트의 철학과 구조는 흥미롭지만, 실제 팀 워크플로우에 넣으려면 기존 개발 방식과 충돌하는 부분이 없는지 확인이 필요합니다.
- “Agent OS”라는 표현은 매력적이지만, 실제로는 아직 빠르게 변하는 개발 도구 생태계 위에 놓인 워크플로우 계층으로 보는 편이 현실적입니다.

## 내 판단

Ouroboros는 “AI가 코드를 대신 짜 준다”보다 한 단계 앞선 문제를 다룹니다. 즉, AI에게 일을 시키기 전에 사람이 무엇을 원하는지 더 정확히 정의하게 만드는 도구입니다.

지인에게 소개한다면 “AI 코딩 도구”라고만 말하기보다, “AI 코딩 전에 요구사항을 제대로 뽑아내고, 그 명세대로 만들고, 다시 검증하는 워크플로우 엔진”이라고 설명하는 편이 정확합니다.

개인적으로는 바로 실무 핵심 도구로 넣기보다, 작은 사이드 프로젝트나 실험용 개발 과제에서 먼저 써 보기에 적합해 보입니다. 특히 요구사항이 자주 흔들리거나, AI가 처음부터 엉뚱한 방향으로 가는 일이 많은 사람에게는 꽤 유용할 수 있습니다.

## 공유 문구 예시

요즘 AI 코딩 도구가 많지만, 이 프로젝트는 “코드를 얼마나 잘 짜느냐”보다 “무엇을 만들지 얼마나 정확히 정했느냐”에 초점을 둔 점이 재미있습니다.

Ouroboros는 막연한 아이디어를 바로 코드로 만들지 않고, 먼저 질문으로 요구사항을 정리한 뒤 명세를 만들고, 그 명세를 기준으로 실행과 평가를 반복하는 오픈소스 도구입니다. Claude Code, Codex CLI, Hermes 같은 런타임도 지원합니다.

AI 코딩을 자주 쓰는데 결과가 자꾸 빗나간다면, 모델 문제가 아니라 요구사항을 충분히 명세화하지 않은 문제일 수 있습니다. 그런 관점에서 한 번 볼 만한 프로젝트입니다.

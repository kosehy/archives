# Graphify 공유용 요약

- 원문: https://github.com/safishamsi/graphify

- 확인일: 2026-05-05

## 짧게 공유할 때

Graphify는 큰 프로젝트를 이해하기 쉽게 지식 그래프로 바꿔 주는 도구입니다. 코드, 문서, PDF, 이미지, 영상 같은 파일을 읽고 개념과 관계를 뽑아 `graph.html`, `GRAPH_REPORT.md`, `graph.json`으로 저장합니다.

요지는 간단합니다. 파일을 매번 처음부터 뒤지거나 grep으로 찾는 대신, 프로젝트 안의 핵심 개념, 연결 관계, 의외의 관계를 그래프로 만들어 두고 그 위에서 질문하자는 접근입니다.

## 조금 길게 설명할 때

Graphify는 AI 코딩 어시스턴트에 붙여 쓰는 지식 그래프 스킬입니다. Claude Code, Codex, OpenCode, Cursor, Gemini CLI, Copilot CLI, VS Code Copilot Chat, Aider, OpenClaw, Hermes 같은 여러 환경을 지원한다고 설명합니다.

사용 방식은 보통 프로젝트 폴더에서 `/graphify .`를 실행하는 식입니다. 그러면 `graphify-out/` 폴더에 세 가지 핵심 산출물이 생깁니다.

- `graph.html`: 브라우저에서 열 수 있는 인터랙티브 그래프
- `GRAPH_REPORT.md`: 핵심 노드, 의외의 연결, 추천 질문을 정리한 보고서
- `graph.json`: 나중에 다시 질문할 수 있는 원본 그래프 데이터

Graphify가 흥미로운 이유는 단순한 요약 도구가 아니라는 점입니다. 코드 구조는 tree-sitter로 결정론적으로 뽑고, 문서나 이미지 같은 비정형 자료는 AI가 의미 관계를 추출합니다. 이후 NetworkX 그래프로 합치고, Leiden 커뮤니티 탐지로 관련 개념 묶음을 찾습니다.

## 무엇을 해결하려는가

- 큰 코드베이스에서 어디부터 읽어야 할지 모르는 문제
- 코드, 문서, DB 스키마, 인프라 설정이 따로 흩어져 있는 문제
- 중요한 설계 이유가 주석, 문서, PR 노트, 이미지 안에 묻히는 문제
- AI 에이전트가 매번 파일을 처음부터 읽느라 맥락을 잃는 문제
- 단순 검색으로는 발견하기 어려운 파일 간 연결을 놓치는 문제

## 동작 방식

Graphify의 README와 문서 기준으로 흐름은 대략 이렇습니다.

1. 파일 탐지: 코드, 문서, PDF, 이미지, 영상 파일을 구분합니다.
2. 코드 구조 추출: tree-sitter로 클래스, 함수, import, call graph, SQL schema 같은 구조를 로컬에서 뽑습니다.
3. 비정형 자료 추출: 문서, 논문, 이미지, 음성 전사본에서 개념과 관계를 추출합니다.
4. 그래프 생성: 노드와 엣지를 NetworkX 그래프로 합칩니다.
5. 클러스터링: Leiden 알고리즘으로 관련 개념 커뮤니티를 찾습니다.
6. 리포트와 시각화: HTML, Markdown 보고서, JSON 그래프를 만듭니다.
7. 재사용: 이후 질문은 원문 전체가 아니라 그래프를 기준으로 처리합니다.

관계에는 `EXTRACTED`, `INFERRED`, `AMBIGUOUS` 같은 신뢰도 태그가 붙습니다. 직접 발견한 관계인지, 합리적으로 추론한 관계인지, 사람이 확인해야 할 관계인지 구분하려는 설계입니다.

## 현재 상태 메모

2026-05-05 확인 기준으로 GitHub 저장소는 약 42,905개의 star와 4,689개의 fork를 가지고 있습니다. 기본 브랜치는 `v7`이고, PyPI 패키지는 `graphifyy`입니다. 확인 시점의 PyPI 버전은 0.7.5이며 Python >=3.10가 필요합니다. 라이선스는 MIT입니다.

GitHub API 기준으로 저장소에는 파일 175개가 있고, 주요 구성은 Python 패키지 `graphify/`, 테스트 `tests/`, 문서 `docs/`, 예제 결과물 `worked/`입니다. 기본 브랜치의 최근 CI는 성공한 이력이 확인됩니다.

## 좋게 보이는 점

- “프로젝트 전체를 AI가 읽는 방식”을 그래프 중심으로 바꾸려는 문제의식이 좋습니다.
- 단순 RAG나 벡터 검색이 아니라, 관계와 커뮤니티 구조를 명시적으로 남깁니다.
- 코드 구조 추출은 LLM 없이 tree-sitter로 처리해 비용과 재현성을 어느 정도 잡으려 합니다.
- HTML, 보고서, JSON을 모두 남겨 사람과 에이전트가 같이 볼 수 있습니다.
- 여러 AI 코딩 환경을 지원하려는 범위가 넓습니다.

## 조심해서 볼 점

- 설치 패키지 이름이 `graphifyy`입니다. 비슷한 이름의 다른 PyPI 패키지와 헷갈리지 않아야 합니다.
- `graphify install`이나 플랫폼별 설치 명령은 에이전트 설정 파일을 바꿀 수 있습니다. 바로 전역 설치하기보다 테스트 프로젝트에서 먼저 확인하는 편이 안전합니다.
- 작은 프로젝트에서는 효과가 크지 않을 수 있습니다. README도 작은 코퍼스에서는 토큰 절감보다 구조적 이해가 주된 가치라고 설명합니다.
- 문서, 이미지, PDF 같은 비정형 자료 추출은 AI 추론이 들어가므로, `INFERRED`와 `AMBIGUOUS` 관계는 검토가 필요합니다.
- 빠르게 업데이트되는 프로젝트라 사용법과 CLI 동작이 버전마다 바뀔 수 있습니다.

## Ouroboros와 비교해서 설명하면

Ouroboros가 “무엇을 만들지 먼저 명세로 정하자”에 가깝다면, Graphify는 “이미 있는 프로젝트와 자료를 그래프로 이해하자”에 가깝습니다.

- Ouroboros: 요구사항, 명세, 실행, 평가 루프
- Graphify: 코드와 문서, 자료를 지식 그래프로 만들고 질의

둘 다 AI 개발을 단순 프롬프트가 아니라 구조화된 작업물로 바꾸려는 방향입니다. 다만 Graphify는 더 직접적으로 코드베이스 이해와 지식 저장에 초점을 둡니다.

## 내 판단

Graphify는 큰 코드베이스나 자료 묶음을 자주 다루는 사람에게 꽤 유용해 보입니다. 특히 프로젝트에 코드뿐 아니라 문서, DB 스키마, 인프라 설정, 연구 자료가 섞여 있을 때 가치가 큽니다.

다만 모든 프로젝트에 기본으로 깔 도구라기보다는, 복잡한 저장소를 처음 파악하거나 여러 문서와 코드가 얽힌 프로젝트를 분석할 때 쓰는 편이 좋아 보입니다. 지인에게 소개한다면 “AI용 프로젝트 지도 생성기”라고 설명하면 이해가 빠릅니다.

## 공유 문구 예시

Graphify는 프로젝트 폴더를 지식 그래프로 바꿔 주는 오픈소스 도구입니다. 코드, 문서, PDF, 이미지, 영상까지 읽고 핵심 개념과 관계를 뽑아서 인터랙티브 그래프와 보고서, JSON으로 저장합니다.

큰 코드베이스를 처음 볼 때 어디서부터 읽어야 할지 모르거나, AI 에이전트가 매번 파일을 처음부터 뒤지는 게 비효율적일 때 유용해 보입니다. 단순 검색보다 “무엇과 무엇이 연결되어 있는지”를 보여 주는 쪽에 가깝습니다.

설치 패키지 이름은 `graphifyy`이고, 여러 AI 코딩 환경을 지원합니다. 바로 전역 설정에 넣기보다는 테스트 프로젝트에서 먼저 돌려 보는 편이 좋겠습니다.

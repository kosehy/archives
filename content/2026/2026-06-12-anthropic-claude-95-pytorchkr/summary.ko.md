# 요약: Anthropic의 Claude 기반 셀프서비스 데이터 분석 스택

## 한 줄 요약

Anthropic의 사례는 “데이터 분석 에이전트의 정확도는 더 똑똑한 SQL 생성보다, 모호성을 줄이는 데이터 거버넌스와 스킬, 검증 루프에서 나온다”는 주장이다.

## 핵심 내용

- Anthropic은 내부 비즈니스 분석 쿼리의 약 95%를 Claude로 자동화하고, 집계 기준 약 95% 정확도에 도달했다고 설명한다.
- 분석 에이전트는 코딩 에이전트와 다르다. 코드는 테스트로 정답 여부를 비교적 명확히 검증할 수 있지만, 분석 숫자는 “어떤 정의, 필드, 기간, 필터를 썼는가”에 따라 그럴듯하게 틀릴 수 있다.
- 주요 실패 모드는 세 가지다.
  - 개념과 엔터티의 모호성: “활성 사용자”, “매출” 같은 말이 여러 테이블, 컬럼, 정의로 갈라진다.
  - 데이터 신선도: 스키마, 비즈니스 정의, 데이터 소스가 계속 바뀐다.
  - 검색 실패: 정답이 문서나 모델 안에 있어도 에이전트가 올바른 조각을 못 찾는다.
- Anthropic의 대응 스택은 데이터 기반, 진실 공급원, 스킬, 검증으로 구성된다.
- 데이터 기반에서는 정규 데이터셋, 강제되는 표준, 코드와 문서의 코로케이션, 메타데이터 품질을 중시한다.
- 진실 공급원은 시맨틱 레이어, 계보와 변환 그래프, 구조화된 쿼리 패턴, 비즈니스 맥락으로 구성된다.
- 스킬은 에이전트가 어떤 순서로 무엇을 참조해야 하는지 알려주는 절차적 지식이다. Anthropic은 스킬이 없을 때 21% 이하였던 분석 정확도가 스킬 추가 후 95% 이상, 일부 도메인에서는 99% 근처까지 올라갔다고 주장한다.
- 검증은 오프라인 평가, 절제 실험, 온라인 검증으로 나뉜다. 특히 “과거 쿼리 전체를 검색하게 해도 정확도는 1%포인트 미만으로만 움직였다”는 음성 결과가 중요하다.
- 최종 메시지는 단순하다. 더 많은 문서를 긁어넣는 것보다, 질문이 하나의 거버넌스된 엔터티로 좁혀지도록 구조를 설계해야 한다.

## 특히 중요한 문장

> 정확도는 코드 생성 문제가 아니라 맥락과 검증의 문제다.

## 실무적 결론

- 데이터 에이전트를 만들 때 먼저 해야 할 일은 “모든 데이터를 검색 가능하게 만드는 것”이 아니라, 정규 지표와 데이터셋을 줄이고 소유권을 명확히 하는 것이다.
- 스킬 문서는 지식 저장소가 아니라 운영 인프라다. 모델, 파이프라인, 지표 정의가 바뀌면 같은 PR에서 함께 갱신되어야 한다.
- 분석 답변에는 출처 계층, 데이터 신선도, 소유자, 검증 여부가 표시되어야 한다.
- 침묵하는 실패, 즉 틀렸지만 그럴듯해서 그대로 쓰이는 답변은 아직 완전히 해결되지 않은 위험으로 남는다.

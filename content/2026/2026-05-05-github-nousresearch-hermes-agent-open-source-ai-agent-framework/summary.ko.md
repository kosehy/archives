# Hermes Agent 공유용 요약

- 원문: https://github.com/NousResearch/hermes-agent
- 저장소: NousResearch/hermes-agent
- 한 줄 설명: 터미널, 메신저, IDE에서 도구를 호출하며 일하는 오픈소스 AI 에이전트 프레임워크
- 확인일: 2026-05-05

## 짧게 공유할 때

Hermes Agent는 Nous Research가 공개한 오픈소스 AI 에이전트입니다. Claude Code나 Codex처럼 터미널에서 작업할 수 있고, Telegram, Discord, Slack 같은 메신저에서도 같은 에이전트를 쓸 수 있습니다. 파일 읽기, 터미널 실행, 웹 조사, 일정 작업, 메시지 전송 같은 도구 호출을 실제 작업 흐름에 묶어 주는 프레임워크에 가깝습니다.

핵심은 단순 챗봇이 아니라 “계속 일하는 개인/팀용 에이전트 환경”이라는 점입니다. 세션, 메모리, 스킬, 툴셋, 플러그인, MCP, 크론 작업, 메시징 게이트웨이를 한 시스템 안에서 다룹니다.

## 조금 길게 설명할 때

Hermes Agent는 AI 모델 하나를 호출하는 래퍼가 아니라, 여러 모델과 도구를 연결해 실제 업무를 수행하게 하는 에이전트 런타임입니다. 사용자는 터미널에서 `hermes`를 실행해 대화할 수 있고, 단발성 명령은 `hermes chat -q "..."` 형태로 보낼 수 있습니다. 설정은 `hermes setup`, `hermes model`, `hermes config`, `hermes tools`, `hermes skills` 같은 CLI 명령으로 관리합니다.

특징은 크게 네 가지로 볼 수 있습니다.

1. 여러 모델 제공자를 바꿔 쓸 수 있습니다. OpenRouter, Anthropic, OpenAI 계열, 로컬 모델, 기타 OpenAI 호환 엔드포인트를 연결하는 구조입니다.
2. 도구 호출을 전제로 합니다. 파일, 터미널, 브라우저, 웹 검색, 이미지, 음성, 일정 작업, 메시징 같은 툴셋을 켜고 끌 수 있습니다.
3. 기억과 스킬을 축적합니다. 사용자 선호, 환경 정보, 반복 작업 절차를 저장해 다음 세션에서 다시 활용합니다.
4. 메신저 게이트웨이를 지원합니다. Telegram 같은 곳에서 에이전트를 호출하고, 로컬 파일과 시스템 도구까지 연결된 작업을 시킬 수 있습니다.

## 무엇을 해결하려는가

- AI 코딩 도구, 리서치 도구, 자동화 스크립트가 따로 흩어지는 문제
- 모델을 바꿀 때마다 워크플로우를 다시 짜야 하는 문제
- 매번 같은 절차와 환경 정보를 다시 설명해야 하는 문제
- 터미널 에이전트와 메신저 에이전트가 분리되어 맥락이 끊기는 문제
- 장기 작업, 예약 작업, 웹훅, MCP, 플러그인 같은 운영 요소를 한곳에서 다루기 어려운 문제

## 주요 기능

- CLI 대화와 단발성 명령 실행
- 모델/프로바이더 설정과 OAuth/API key 기반 인증
- 파일, 터미널, 웹, 브라우저, 비전, 음성, 메시징 등 툴셋 관리
- 세션 저장, 세션 재개, 컨텍스트 압축
- 사용자 메모리와 절차형 스킬 관리
- Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Email 등 게이트웨이
- MCP 서버 등록과 Hermes 자체 MCP 서버 실행
- 크론 작업과 웹훅 기반 자동 실행
- 프로필을 통한 독립 인스턴스 분리
- 플러그인과 커스텀 도구 확장

## 좋게 보이는 점

- 단순 터미널 챗봇이 아니라 업무 운영 계층까지 포함합니다.
- 메신저에서 로컬 도구를 호출할 수 있어 모바일/원격 작업 흐름과 잘 맞습니다.
- 스킬과 메모리 중심이라 반복 작업이 누적될수록 환경에 맞춰집니다.
- 모델 제공자에 덜 종속되는 구조라 특정 벤더에 묶이지 않습니다.
- MCP, 웹훅, 크론, 플러그인까지 열어 두어 확장성이 큽니다.

## 조심해서 볼 점

- 설치 스크립트와 게이트웨이는 로컬 설정, 서비스, 인증 정보를 다룹니다. 바로 전역 설치하기보다 문서를 읽고 테스트 환경에서 확인하는 편이 안전합니다.
- 도구 호출 권한이 넓은 에이전트라 터미널, 파일, 메시징 권한을 어떻게 제한할지 먼저 정해야 합니다.
- 메신저 게이트웨이는 편하지만, 봇 토큰과 채널 권한을 잘못 관리하면 예상보다 넓은 권한을 줄 수 있습니다.
- 메모리와 스킬은 장점이지만, 팀 환경에서는 무엇을 저장할지 규칙이 필요합니다.
- 빠르게 개발되는 프로젝트라 CLI 옵션과 설정 키는 현재 문서를 기준으로 재확인해야 합니다.

## Graphify, Ouroboros와 비교해서 설명하면

- Hermes Agent: 에이전트를 실행하고 도구, 메모리, 메시징, 예약 작업을 운영하는 런타임
- Graphify: 코드와 문서 묶음을 지식 그래프로 바꾸는 분석/이해 도구
- Ouroboros: 만들기 전에 요구사항과 명세를 정리하고 실행/평가 루프를 돌리는 워크플로우 도구

셋을 묶어 보면 Hermes가 “일하는 에이전트의 실행 환경”, Graphify가 “프로젝트 지식 지도”, Ouroboros가 “명세 기반 작업 루프”에 가깝습니다.

## 내 판단

Hermes Agent는 AI 에이전트를 실제 업무에 붙여 쓰려는 사람에게 가장 직접적인 기반 도구입니다. 단순히 코드를 생성하는 도구라기보다, 작업 요청을 받고, 필요한 파일과 웹을 읽고, 명령을 실행하고, 메신저로 결과를 돌려주는 운영 프레임워크입니다.

다만 권한이 큰 만큼 “무엇을 허용할지”가 중요합니다. 개인 환경에서는 생산성이 크지만, 조직 환경에서는 프로필, 툴셋, 게이트웨이 권한, 메모리 저장 범위, 비밀정보 관리 규칙을 먼저 잡아야 합니다.
